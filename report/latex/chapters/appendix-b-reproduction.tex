\section{Local reproduction commands}

With Python 3.12, \texttt{uv}, and the frozen inputs restored, the project records
these offline commands:

\begin{verbatim}
uv sync --locked --group dev --extra analysis --extra report
uv run research-network schema
uv run pytest

mkdir -p reports/reproduction-v4

uv run research-network validate \
  --input data/processed/release-graph-v4/graph.json \
  --config configs/quality-release-v1.yaml \
  --require-size \
  --output reports/reproduction-v4/validation.json

uv run research-network analyze \
  --input data/processed/release-graph-v4/graph.json \
  --config configs/analysis-release-v1.yaml \
  --quality-config configs/quality-release-v1.yaml \
  --output reports/reproduction-v4/analysis.json
\end{verbatim}

Replay commands use new output locations; they should not overwrite the frozen
graph, analysis, or audit results. The exact frozen-input restoration procedure,
source hashes, and graph correction details are documented in
\sourcepath{docs/reproduce-remediation-v4.md}. Reacquiring current API data is
not a byte-identical substitute for the original cached responses.
