## Objective

Rebuild the Research Trend Navigator frontend on the approved design mockup
(`apps/research-explorer/design-mockup/`) in six phases: tokens, fonts, shell and
routing; Ask; Pulse, Trends and Topic; Groups, Map and Network; Node profile, About
and Explore; quality pass. Keep every feature, endpoint and test working, change
the answer prompt to a summary-first format (new version), re-cache the 7 demos on
`enriched-cb371912e308`, and leave v4 behaviour unchanged.

## Changes and findings

Phase notes are appended below as each phase is committed.

### Phase 1: tokens, fonts, shell and routing

- **Tokens** (`frontend/src/styles/index.css`, `tailwind.config.js`): the mockup's light and dark
  CSS variables (chart paper, graphite, rule, sunken, cooling/stable/heating with AA text inks,
  entity hues; Researcher `#557626` and Topic `#B04A5A` added as muted hues). Legacy names
  (`--ground`, `--text`, `--border`, `--accent`, pills, chart colours) are aliases, so the v4
  Explorer restyles without logic changes. `--faint` is darkened to `#5F6D80` (4.9:1 on paper)
  because the Explorer uses it for text; the mockup's `#7A8794` survives as `--decor` for strokes.
- **Fonts** (`styles/fonts.css`): self-hosted through `@fontsource` (Atkinson Hyperlegible Next 400/500/700,
  Source Serif 4 variable with optical size). Atkinson Next's zero is slashed and the font has no
  unslashed alternate (checked with fontTools: features `ccmp frac locl pnum tnum`, glyphs
  `zero`, `zero.tf` only), so digits 0-9 come from Source Sans 3 through a digits-only
  `unicode-range` face ("RTN Figures") with tabular figures.
- **Theme:** light first; a stored choice wins, otherwise the OS preference, otherwise light.
- **Shell** (`components/shell/AppShell.tsx`): one left rail (Pulse, Ask with recent conversations,
  Trends, Topics, Groups, Map, Network, Explore, About at the bottom), a top bar with the global
  search trigger (⌘K, `/`) and theme toggle, and a bottom tab bar with a More sheet at ≤768 px.
  The old double header and the "NAVIGATOR" strip are gone; `TopHeader` became
  `components/explore/ExploreToolbar.tsx` (Graph/Table, Paths, Compare, Caveats, share/export).
  The version hash is no longer printed in the chrome: the toolbar says "Release graph v4" with
  the hash on hover, and About lists every version.
- **Routing** (`lib/router.ts`): real paths (`/`, `/ask/:conversation`, `/trends`, `/topics/:id`,
  `/groups/:id`, `/map/:id`, `/network`, `/network/release`, `/explore`, `/explore/table`,
  `/node/:id`, `/about`), History API with Back/Forward, and legacy URLs (`/?tab=…`, `/?mode=…`,
  `/?view=…`) rewritten on load. The store's `workspaceTab` stays the Explorer's source of truth and
  is synchronised both ways with the path, so existing `openSubject`/`setWorkspaceTab` calls work.
- **Global search** (`components/search/NavigatorSearchModal.tsx`): subjects plus enriched-graph
  organizations, researchers and papers; each hit opens its page; Enter with no hit asks the
  question. Inside Explore the v4 `SearchCommandModal` is unchanged.
- **Explore** (`components/explore/ExplorePage.tsx`): the Explorer logic moved out of `App.tsx`
  unchanged (view query, effective slice, expansion, scope restore); the sidebar-folding
  breakpoints are measured on the Explore area (viewport minus the 232 px rail).
- **v4 analytics placement:** the v4 Analytics dashboard is now Network → "Release graph (v4)
  analysis" (`/network/release`); `/?tab=analytics` redirects there.
- **v4 test navigation only** (`tests/helpers/nav.ts`): `goto("/")` → `goto("/explore")`; the
  version badge check reads the hover title; in-page Analytics/Graph tab clicks go through the
  rail (or the tab bar's More sheet at 768 px). Explorer assertions are unchanged.

### Phase 2: Ask

- **Page** (`frontend/src/components/navigator/AskPage.tsx`, `components/ask/*`): conversation on the
  left (welcome with starter cards grouped as Trends, Groups, Connections and Overview from the 7
  scripted demos; user bubble; a live Plan driven by `status`/`parsed`/`plan`/`step` events with a
  spinner then a check per step, collapsing to "N steps, all done"; the answer in Source Serif 4
  typed out from `token` events with numbered footnotes; a quiet check line or a clear warning with
  what did not match; follow-up chips; disambiguation and "use the task instead" choices without
  IDs; a composer with an advanced menu for Auto/Local/Global and "Use cached demo answers").
  Evidence on the right with ARIA tabs and counts: Graph, Chart, Table, Papers.
- **Presentation model** (`lib/askModel.ts`): plain-language step titles and results per tool,
  tables with plain column names and formatted values, automatic chart choice (lines for trends;
  ranked bars, or a before/after dumbbell when some "before" values are non-zero, for share
  changes; bars for rankings and co-occurrence, one panel per kind), deterministic graph layouts
  (funnel for collaborator→subject walks, bow tie for method→tasks/datasets, fan for scoped
  rankings, chain for paths, layered otherwise) revealed hop by hop as steps finish, and footnotes
  from `[step N]`, `[paper:…]` and list items that match a result row. Community IDs in global
  answers are rewritten as "a research community focused on …". Cached demo events are paced on the
  client so the reveal reads like a live run; `prefers-reduced-motion` shows everything at once.
- **History:** conversations in `localStorage` (`lib/conversations.ts`, 20 kept, rows trimmed),
  listed under Ask in the rail; `/ask/<id>` restores the answer and evidence without re-running.
- **API addition:** `GET /api/papers?id=…` (≤60 ids) returns title, venue, year, first authors, link
  and in-corpus citations, so papers are shown by title (`backend/services/navigator_service.py`,
  test `test_papers_lookup_returns_titles_not_ids`). No existing route or SSE event changed.
- **Answer format:** new prompts `rag-answer-v5` and `rag-local-answer-v4` (`src/scientific_network/rag/answer.py`);
  `dev_eval.py` gained `--answer-prompt`, `--local-answer-prompt`, `--dev-out`, `--dev-only` and
  answer-shape metrics; `demo-cache.json` now records graph and prompt versions. Development figures
  (19 kept dev questions only): faithfulness 0.9474 → 0.9474 (same single global failure, unchanged
  global prompt), scores identical, bullets per answer 5.16 → 3.00 (max 20 → 8), words 62.8 → 54.6,
  first sentence 293.6 → 154.9 characters. The 7 demos were re-cached without the LLM cache on
  `enriched-cb371912e308`: 7/7 faithful (demo-04 asks for a choice), total latencies 2.4–51.7 s.
  Dated note in `reports/final-exam/qa-eval-v1/results.md`; frozen tables untouched.
- **Live check through the UI** (cache off, new question "Which organizations specialize most in
  federated learning by lift?", not a test question or near-paraphrase): plan steps streamed, graph
  revealed at 39.7 s, answer text from 46.4 s, finished 47.1 s, faithful

### Phase 3: Pulse, Trends and Topic

- **Pulse** (`PulsePage.tsx`): headline generated from the trend data; thermal strip of 12 subjects
  (7 heating, 2 stable that moved most, 3 declining; methods and tasks with at least 20 papers); compact
  Ask box with 3 starters; "Who leads the rising topics"; "Is it a small world?" with a link to Network.
  New precomputed `GET /api/pulse` (test `test_pulse_strip_leaders_and_small_world`).
- **Trends:** filters, generated headline, one chart of user-picked series (default: the 4 fastest
  heating; at most 6) with removable chips as the legend, three leaderboards with chart toggles, and
  a year-by-year heat table with a wide, wrapping label column. Line charts now draw at their
  container width (ResizeObserver), so labels stay at 12 px or more on phones.
- **Topics:** `/topics` is a searchable index. A topic page has a generated hero sentence, the share
  chart, leading groups with specialisation bars, "Often found together" chips with shared-paper
  counts, "In brief" (written from the page's counts, footnoted, and labelled as not model-written),
  the Wikipedia or AI-generated description, the related community report (labelled AI-generated,
  with numbered paper sources) and top papers by title.
- **API additions (fields only):** subject detail gains `leading_groups` (same rule as Pulse),
  `min_org_papers`, `co_mentions`, `researcher_evidence` and `description`; the subject list gains
  yearly `shares`. Test `test_subject_detail_ranks_groups_with_minimum_evidence`.
- **Display rules** (`frontend/src/config/display.ts`; analysis classes unchanged): a Stable subject
  whose share changed by at least 0.3 points and 1.5 times reads "Grew, not consistently" or
  "Fell, not consistently". Organizations need 3 papers on a subject to be ranked and researchers 5;
  both thresholds are stated in the ⓘ popover. When no researcher reaches 5, the page says so and
  gives the highest count instead of ranking.
- **Change from the old page:** leading groups are ranked by relative concentration (the share
  ratio), as on Pulse. The old researcher list by PageRank lift (2-paper minimum) is below the new
  threshold and is no longer shown. The organization PageRank-lift table is not on the page either;
  the values stay in the API (`top_organizations`).
- Checks at this checkpoint: `uv run pytest -q` 796 passed, 1 skipped; navigator API tests 8 passed;
  `npm run build` succeeded.
