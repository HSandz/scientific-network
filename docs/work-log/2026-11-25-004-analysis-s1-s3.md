## Decisions

- **Ministry rule (declared change 2026-11-25, before any roll-up).** The reviewer's 48 ministry `PART_OF` edges are reproduced by the parent's name containing "ministry"; the class-label rule flags 78 and over-reaches (Tsinghua, US federal departments). Name rule adopted; disclosed in the config `changes` and the specification note.
- **Presentation rules** (specification §5.3 dated note): roll-up along `PART_OF` only, `MEMBER_OF` never, ministry parents skipped; community labels are c-TF-IDF terms only; "lab" is an organization-anchored N1 community and is labelled an approximation.
- **Hierarchy level 1 (declared change 2026-11-25, after the first S3 run, before the level-1 result was read).** Leiden at resolution 1.0 on the contracted graph merged nothing, so level 1 uses 0.25, run once and not tuned. Outcome: N1 3,029 → 2,973 level-1 communities (small components dominate);
  N2 117 → 105, with 1,837 of 2,047 organizations in one community, so N2's level 1 is not useful. For M3, N2 should use the 0.8/1.2 partitions as alternative levels or a different hierarchy; that needs a new dated decision, not a silent change.
- Only the 16 leaf topics carry papers, so "all 20 topics" in the config means 16 for personalized PageRank and trends; the 4 parents have no `HAS_TOPIC` edges.
- Whole-graph community modularity on N1 is inflated by 2,936 components; the README reports LCC-restricted figures beside it.
- Stopped `scientific-network-neo4j-enriched-1` for RAM during the runs and started it again afterwards.
