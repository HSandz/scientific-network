## Objective

Implement the data-enrichment track (E1–E4) per `docs/final-exam/specification.md`
§4, starting with the M0 gate: frozen enrichment splits, frozen QA question text,
the LLM client and the K1 model-selection experiment on development papers only.

## Changes and findings

- Starting state verified: `sn-llm` healthy (Qwen3.5-4B Q4_K_M); `enrichment-splits-v1`
  did not exist; `~/models/gguf/` held only the Qwen GGUF.
- **Splits frozen** (commit `7af92eb`): `data/manifests/enrichment-splits-v1/`, seed 20261124,
  100 development and 200 test papers, venue-year stratified, drawn from 13,608 papers with a
  non-empty abstract (the specification says 13,606; the measured count is 13,608, 9 papers have
  no OpenAlex record). Overlaps with earlier audit samples and `five-year-splits-v1` are in
  `receipt.json`.
- **QA benchmark text frozen** (same commit): `data/manifests/qa-benchmark-v1/`, 80 test
  (20/25/20/15 by hop class) and 20 development questions, generated from templates in
  `src/scientific_network/enrich/benchmark.py` without any v5 or model output. Reference answers
  are pending v5.
- **LLM client** `src/scientific_network/rag/llm.py`: schema-constrained JSON, one retry, disk
  cache keyed on (model, revision, prompt version, input hash), call log. Fake-server tests; a live
  call against `sn-llm` returned a valid schema answer and a cache hit on repeat.
- **Development reference labels frozen before any model ran on a development paper** (commit
  `6603fb2`, 2026-11-24 11:17 +07:00): 100 papers, 326 methods, 113 tasks, 29 datasets, 84
  APPLIED_TO and 28 EVALUATED_ON relations, written by this agent (Claude Sonnet 5.5) under
  `docs/final-exam/enrichment-labeling-guideline-v1.md`. AI-assessed, single labeller, not gold.
- Specification conflict recorded: spec §4.2 step 2 has the SLM verify spans per sentence. The
  development experiment prompts per paper (title and abstract, candidates numbered) because
  one call per paper is cheaper and gives the model the context that decides whether a method
  is used; the evidence sentence is derived from the span offsets. Revisit if it hurts.
- Encoders run on CPU over the 100 development texts (GLiNER2.5 335 ms/doc, GLiNER-Relex
  1,035 ms/doc). Thresholds tuned on development only.

- **K1 result** ([report](../../reports/enrichment-v1/k1-model-selection.md)), dev entity F1 lenient
  (relation F1): Qwen3.5-4B encoder+SLM 0.670 (0.400); Gemma-4-E4B-it 0.624 (0.272);
  Qwen3.5-9B reference 0.662 (0.373). Encoders alone: GLiNER-Relex 0.556, GLiNER2.5 0.468.
  Qwen3.5-4B and GLiNER-Relex chosen; the 9B misses the §6.1 margin. Prompts went through
  verify v1 to v5 plus a relation-generation step; a one-call JSON verify over-dropped and a
  pointwise verify was too slow (972k prompt tokens), so the final verify uses single-letter batch
  decisions. Prompts were tuned with Qwen3.5-4B in the loop (disclosed bias).
- **E1 sources** (`reports/enrichment-v1/sources.json`): 13,608 of 13,617 papers have an OpenAlex
  abstract (9 title only); 2,047 v4 organizations carry a ROR ID and 2,044 matched Wikidata by P6782
  with no name matching (0 ROR conflicts, sector from Wikidata classes); 1,468 Wikipedia pages (lead
  and infobox, revision IDs stored) for 1,462 organizations. Raw responses are in the ignored
  `data/raw/enrichment-v1/` with a fetch manifest; `docs/source-policy.md` treats Wikipedia as
  enrichment only, so the repository publishes IDs, offsets and spans, not page text. Wikidata
  researchers and news sources were not run (optional).
- Bug found and fixed: `str.splitlines()` also splits on U+2028, which occurs in some abstracts,
  and corrupted JSONL reads in the fetcher and extraction scripts; reads now iterate by line.
- Specification conflict recorded: the specification says GLiNER2.5 is the default extractor; the
  prompt and spec §4.2 let the development split pick it, so GLiNER-Relex was chosen (D042 amendment).
